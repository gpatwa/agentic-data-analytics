# Databricks spike: the exact statements and calls (generated)

Generated by `services/analytics-api/app/connect/e2e/databricks_spike.py`; a test keeps this file equal to the generator. `a1b2c3d4` stands for the fresh 8-hex run suffix chosen at run time; `<S_APP_ID>` and `<T_APP_ID>` for the application ids of the setup principal `S` and the connection principal `T`, which exist only after they are created; the warehouse is chosen by name (`Serverless Starter Warehouse`) and never edited. **Nothing here has been run.** Plan: `docs/design/CONNECT_DATABRICKS_SPIKE_PLAN.md`.

Every statement below must mention this run's catalog; the driver refuses anything else (no users, groups, metastore, owner or other catalog). Plain `CREATE` is used throughout, never `IF NOT EXISTS` or `OR REPLACE`. Order of the questions at run time: Q7 (decoy), Q1, Q2, Q3, Q4, Q6, then Q5 (rollback), so the principal exists while the read checks run.

**Not built:** the fallback of using a schema inside an existing catalog. If the workspace refuses `CREATE CATALOG`, the run stops at the first fixture statement with nothing created (teardown has nothing to remove) and the fallback needs a small change and your approval before another run. Granting `USE CATALOG` on a catalog you own would also need explicit revokes at teardown.
